## At a glance

| | |
|---|---|
| **What** | A light Android app that follows GPX routes on a mountain bike with arrow guidance, over offline OpenStreetMap-based maps. |
| **Who** | The owner and a few friends. Sideloaded APK (or Play closed testing). No server. F-Droid possible later. |
| **Core loop** | Import GPX → pick a route (stars, "near me") → ride with turn banner / big arrow + beeps → ride saved to history. |
| **Stack** | Kotlin · Jetpack Compose · VTM (offline Mapsforge `.map`) · Room · DataStore · pure-Kotlin navigation engine. No Google Play Services. |
| **Maps** | OpenAndroMaps (MTB difficulty S0–S5, trail visibility, contours) installed via user-initiated links, own MTB render theme. |
| **Test phone** | Motorola Moto G15 (budget chipset, LCD, ~5,200 mAh, single-band GPS, Android 15). |
| **Top risk** | Guidance quality from a plain GPX track (no turn data) on twisty singletrack with single-band GPS — mitigated by switchback grouping, progress-aware matching, replay-driven tuning, and junction-aware turns in v2. |

## 1. Problem & goals

Following a GPX route on a mountain bike today means either a heavyweight app (OsmAnd: powerful but cluttered and slow to operate on the trail) or a commercial one (komoot, Locus). The owner wants something **simpler and focused**: a personal library of routes with descriptions and stars, and a glanceable ride screen whose job is to tell you *which way to go next*.

**Design principle:** lighter and simpler than OsmAnd. Every feature must earn its place on a handlebar-mounted phone.

### Goals (v1)
- Keep a library of GPX routes with name, description, personal 1–5 stars, elevation profile and stats, distance to the nearest point of the route ("near me"), and ride history.
- Import from Android share / "open with", an in-app file picker, a watched folder, and direct `https` URLs.
- Guide a ride along a route with a **turn banner + map** view and a **big arrow** view (swipe between them), beep tones, off-route return guidance, start-from-nearest-point, reverse riding, and auto-detected reverse direction.
- Show offline OpenAndroMaps vector maps with an MTB-oriented theme.
- Record the ridden track, view it, export it as GPX, and delete it.
- Share routes with friends without leaking personal ride history; full manual backup/restore.
- Survive crashes, swipe-away and reboots mid-ride without losing guidance or the recording.

### Non-goals
- Route planning or re-routing along trails (no BRouter / routing graph).
- Voice instructions and vibration alerts (beeps only).
- Any server, account, cloud sync, social features, Strava auto-upload.
- Online map tiles, bulk tile prefetching.
- Notes on routes. (Grouping routes into collections is in: D48.)
- iOS, Wear OS, bike computers.
- Commercial distribution.

## 2. Users, distribution & licensing

- **Audience:** owner + a few friends. Each phone has its own independent library.
- **Install:** release APK shared directly, or Play Console closed testing. Location-permission justification text is written anyway (§9.3).
- **F-Droid-ready by default:** no Google Play Services, no Firebase/Crashlytics, no Google Maps, no closed-source SDKs. Location comes from Android's `LocationManager` (`GPS_PROVIDER`). Every dependency must be open source.
- **Signing:** one release keystore, generated by the owner, used for every channel. If Play is used, upload this key as the **app signing key** (not a Google-generated one). Keep two offline backups of the keystore and its passwords. Debug builds use `applicationIdSuffix = ".debug"` so they install side by side with release. Aim for F-Droid reproducible builds later, so F-Droid can ship the owner-signed APK.
- **Third-party terms:**
  - OSM data: ODbL. Attribution "© OpenStreetMap contributors" is always visible on the map.
  - OpenAndroMaps maps: free for private use. Direct links and bundling are forbidden without written permission. The app only reacts to install links the user taps on the OpenAndroMaps website.
  - OpenAndroMaps `andromaps_*` render themes may be integrated. The Elevate/Elements themes may not be bundled, but the user can load them.
  - Mapsforge/VTM: LGPL-3.0 (with Mapsforge's §4(d)/(e) waiver). Compatible with any app licence.
- **App code licence:** GPL-3.0 (D45). The bundled theme files (`app/src/main/assets/theme/`) stay under OpenAndroMaps' terms; their author asks for a short notice from apps that integrate them.

## 3. User journeys

1. **Receive a route.** A friend sends a `.gpx` on WhatsApp. Tap it → "Open with Singletrail" → import preview (name, distance, climb, map thumbnail) → *Add to library*.
   - If the route already exists: "Already in library".
   - If it looks like an updated version: "Update existing route / keep both".
2. **Choose today's ride.** Library sorted by *near me*, narrowed to a collection and filtered by stars, length, climb, not ridden yet or loops. Open a route to see the map, elevation profile, stats, description, your stars, past rides and the map coverage check → *Ride* / *Ride reversed*.
3. **Install a map.** Maps screen → *Get maps* opens openandromaps.org in the browser → tap the region's install link → Singletrail confirms region, size and free space → download → unpack → ready. A `.map` file from a PC can also be imported manually.
4. **Ride.**
   - Tap *Ride* → audio check (test beep).
   - "Waiting for GPS" → matched to the nearest point → guidance starts.
   - Banner/arrow, beeps before turns, the screen dims between turns.
   - Off-route alert with a return arrow, back-on-route tone.
   - "Riding reversed?" auto-accepts after 10 s.
   - Finish → summary.
5. **After the ride.** Summary (distance, moving time, climb) → rate the route → the ride appears in history; the track can be viewed or exported as GPX.
6. **Share / back up.**
   - *Share routes* sends GPX (name + description only) through the share sheet.
   - *Full backup* creates a zip that is clearly labelled as containing location history.
   - *Import* detects which kind of file it is.

## 4. Ride experience

### 4.1 Two views, swipe to switch (remembers the last one)

**Map view**
- **Top banner:** next maneuver icon + distance ("↰ 120 m"). If the following maneuver is close, a second line ("then ↱ 40 m").
- **Map:** heading-up by default (north-up toggle). The route ahead is drawn in route colour and the ridden part greyed. Turn markers and GPX waypoints are shown.
- **Bottom bar:** distance left, climb left, GPS status, battery.
- **Switching:** swipe from the arrow view, or tap the page names. On the map every drag moves the map, so the page names switch back.

**Arrow view**
- One large arrow pointing at a look-ahead point on the route (30–60 m ahead, speed-adaptive), relative to the rider's heading (§5.9).
- Below it: "next ↰ in 120 m", distance left, climb left.

### 4.2 Ride states (shown in both views, never by auto-switching views)

| State | Banner / arrow | Sound |
|---|---|---|
| Waiting for GPS | "Waiting for GPS · 7 satellites" | — |
| Acquiring (far from route) | Arrow to nearest route point + distance | — |
| On route | Next maneuver + distance | approaching / now tones |
| Off route | Amber banner "⚠ 38 m off route", return arrow + distance | off-route tone, back-on-route tone |
| No GPS (no fix ≥ 10 s) | Grey arrow, "last fix 40 s ago", alerts paused | signal-lost tone, signal-back tone |
| Compass mode (slow/stopped) | Small compass marker on arrow | — |
| Reverse detected | "Riding reversed? Switching in 10 s" + Undo | prompt tone |
| Finished | Summary card | finish tone |

### 4.3 Beep tones
- **Six distinct short tones:** turn approaching, turn now, off route, back on route, signal lost, signal back. Two more cover reverse prompt and finish.
- **Audio channel:** `AudioAttributes.USAGE_ALARM`, so beeps play in silent and vibrate mode. They have their own in-app volume, independent of media volume.
- **Ride-start audio check:** plays a test beep, then warns if alarm volume is 0, Do Not Disturb would block alarms, or audio is routed to Bluetooth.
- **Timing:** see §5.10.

### 4.4 Screen & power (v1)
- **Screen:** kept on during a ride (`FLAG_KEEP_SCREEN_ON`) by default.
- **Dim between turns:** window brightness drops to a user-set dim level and returns to full about 15 s before a maneuver, on off-route, and on no-GPS. Uses window brightness only; no special permission.
- **Redraw:** the map redraws only on new fixes (≤ 1 Hz) or user interaction, with no idle animations.
- **Battery levels:**
  - At 30%: a warning.
  - At 20%: offer **low-power mode**, which shows the arrow view only, hides the map and keeps the screen dimmer.
- **Battery Saver:** check its location mode (`PowerManager.getLocationPowerSaveMode()`) at ride start and whenever it changes, and warn if GPS would stop with the screen off.
- **v2:** screen-off mode that wakes the screen near turns, using a full-screen-intent notification and `USE_FULL_SCREEN_INTENT`.

### 4.5 Ride lock (rain, mud, gloves)
- While riding, touches are ignored except a deliberate **long-press to unlock** (shown as a lock icon).
- *Stop ride* needs a long-press plus a confirmation.
- After manual panning, the map returns to follow mode after about 10 s.
- Prompts that need an answer (reverse) **auto-accept after 10 s** with a tone and offer *Undo*.
- While the app is in the foreground, **volume keys** act as accept/undo for the active prompt.
- Sunlight and gloves: high-contrast theme (not dark — the G15 has an LCD), large type, touch targets ≥ 64 dp on the ride screen.

### 4.6 Ongoing notification
Shows the route name, the next maneuver and the distance. Tapping it opens the ride screen. There is no stop action in the notification; stopping always happens in the app with confirmation.

## 5. Navigation engine (`:core:nav`, pure Kotlin/JVM)

The engine is a deterministic function of *(route, config, stream of fixes, stream of heading samples)*. This makes it fully unit-testable and replayable from recorded traces.

### 5.1 Interfaces (sketch)
```kotlin
data class Fix(
    val elapsedNanos: Long, val lat: Double, val lon: Double,
    val accuracyM: Float?, val speedMps: Float?, val bearingDeg: Float?,
    val bearingAccDeg: Float?, val altitudeM: Double?, val satellites: Int?
)
data class HeadingSample(val elapsedNanos: Long, val azimuthDeg: Float, val reliable: Boolean)

class Navigator(route: PreparedRoute, config: NavConfig, mode: RideMode) {
    fun onFix(fix: Fix): NavUpdate          // state + events
    fun onHeading(sample: HeadingSample): NavUpdate
    fun onTick(elapsedNanos: Long): NavUpdate // detects "no GPS" when fixes stop
    fun snapshot(): NavCheckpoint             // for crash recovery
    companion object { fun restore(route: PreparedRoute, cp: NavCheckpoint): Navigator }
}
```

### 5.2 Route preparation (at import, cached)
- Drop consecutive points closer than 1 m.
- Compute cumulative distance (haversine).
- Build a segment grid index (~50 m cells) for nearest-segment queries.
- Smooth elevation (60 m moving window + 5 m hysteresis for ascent/descent).
- Loop flag: start and end less than 50 m apart.
- Resample a 5 m polyline for turn detection.
- Limits: more than 200,000 points or a file over 20 MB is rejected. A warning above 50,000 points.

### 5.3 Turn detection v1 — geometry
- For each resampled point, compute the heading change Δ between the incoming bearing over the previous 20 m and the outgoing bearing over the next 20 m.
- **Corner vs curve:** a candidate needs |Δ| ≥ 40° accumulated within ≤ 25 m. This separates corners from long sweeping curves.
- Non-maximum suppression within 30 m.
- **Classes:** slight 40–60° (icon only, no beep by default), turn 60–120°, sharp 120–165°, U-turn > 165°.
- **Switchback grouping:** three or more sharp/U-turns alternating sides within ≤ 250 m along the route (first to last) become one maneuver, "Switchbacks ×N". A longer stack becomes several groups. Each group gets one *approaching* alert and no *now* alerts.
- **Storage:** computed for both forward and reverse directions and stored with an `algoVersion`. *v1 computes them when a ride starts instead (D44).* Recomputed when the algorithm version changes, and (v2) when maps covering the route are installed.
- All thresholds live in `NavConfig` and are tuned with replayed rides.

### 5.4 Turn detection v2 — junction-aware
- Read ways (`highway=path|track|footway|bridleway|cycleway|…`) near the route from the installed `.map` files, using high-zoom data.
- Find junction nodes where another way meets the route within about 10 m.
- Announce maneuvers only at junctions. Where the route goes straight but a branch leaves at less than 30° from the route, announce "keep left/right".
- Fall back to v1 geometry for parts of the route without map coverage.

### 5.5 Progress-aware matching
- **State:** progress `s` (metres along the route).
- **Accuracy gate:** fixes with accuracy > 25 m update only the "no GPS / poor GPS" indicators. They never trigger off-route alerts.
- **Candidates:** segments within the window `[s − 150 m, s + max(400 m, 60 s × speed)]`.
- **Scoring:** distance plus heading consistency (rider course vs segment bearing when moving).
- **Monotonic progress:** `s` only moves forward, except for jitter of up to 30 m backwards.
- **Out-and-back and figure-8 overlaps:** resolved by the window, which never includes an overlapping segment far from `s`.
- **Global search:** whole-route search, preferring points ahead, is used only while ACQUIRING and after a long detour (§5.7).

### 5.6 State machine
```
WAITING_GPS ─fix─▶ ACQUIRING ─match within T─▶ ON_ROUTE ◀──────────────┐
                                    │                                  │
                         dist > T for ≥3 good fixes / ≥5 s      dist < T−10 m ×2
                                    ▼                                  │
                               OFF_ROUTE ──────────────────────────────┘
ON_ROUTE ─consistent backwards ≥100 m─▶ REVERSE_PENDING ─10 s / accept─▶ ON_ROUTE (reversed)
                                                └─ undo ─▶ ON_ROUTE (suppress 500 m)
any ─no fix ≥10 s─▶ NO_GPS (overlay; previous state kept) ─fix─▶ previous state
ON_ROUTE ─within 30 m of finish after ≥90% progress─▶ FINISHED
```
`T` is the off-route threshold: 30 m by default, configurable from 15 to 80 m. Going off route needs both: at least 3 good fixes in a row beyond `T`, spanning at least 5 s. A loop (including an out-and-back whose ends are within 50 m) is rotated at the first match to start at that point, so it finishes there after one lap.

### 5.7 Off-route return target (revised by red team)
- **Short detour** (less than 300 m ridden off-route):
  - Target the **exit point**, where the rider left the route at progress `s_exit`.
  - Switch to a target ahead (`s > s_exit`) only if it is ≥ 50% closer than the exit point **and** the rider's distance to it has been decreasing for about 20 s.
- **Longer detour:** target the nearest route point ahead within a 2 km window.
- **Switchback rule:** never pick a target, and never jump progress, past a switchback group or turn cluster between `s_exit` and the candidate that hasn't been ridden. This prevents "cut straight down the slope" arrows.
  - In the engine, every sharp turn and U-turn (grouped or not) is such a barrier. It counts as ridden once progress is 10 m past it with the rider's course along the route there. Until then matching reaches at most 20 m past it, and targets stop at it.
- **Rejoining:** when back on the route at `s_rejoin > s_exit`, the section in between is marked as skipped and its maneuvers are dropped.
- **Map view:** the route line is always shown, because the arrow is a straight line and may cross terrain.

### 5.8 Ride modes
- **Start from nearest point** (always on).
  - While ACQUIRING, the arrow points to the nearest route point.
  - The first match sets `s_start`.
  - On loops, progress wraps and the ride finishes when the rider returns to `s_start`.
  - On point-to-point routes, the part before `s_start` is skipped.
- **Ride reversed:** reversed geometry with the reverse maneuver list. Chosen at start or by auto-detection.
- **Auto-detect reverse:**
  - Triggers when the rider's course is opposite (> 135°) to the expected segment at `s`, `s` is decreasing consistently for ≥ 100 m, and speed is > 2 m/s.
  - Leads to REVERSE_PENDING.
  - Overlapping out-and-back return legs don't trigger it, because matching stays continuous at `s` (§5.5).
- No "navigate to start" mode. When the rider is far from the route, the ACQUIRING arrow covers it.

### 5.9 Heading source
- **Riding (speed ≥ 6 km/h** and GPS bearing accuracy ≤ 30°): use GPS course.
- **Slow or stopped:** use rotation-vector sensors (compass + gyro), remapped for a phone standing upright on the bars. A compass-mode marker is shown, plus a calibration hint when the sensor reports low accuracy.
- **"Compass off" setting** (for magnetic mounts): below 6 km/h, freeze the last heading and grey out the arrow. The map switches to north-up with a bearing line to the target.

### 5.10 Alert timing (speed-adaptive)
- **Inputs:** `v` is speed smoothed over about 5 s. The position is extrapolated along the route by the fix's age (`elapsedRealtimeNanos` delta).
- **Approaching:** when distance to the maneuver ≤ `max(80 m, 12 s × v)`.
- **Now:** when distance to the maneuver ≤ `max(15 m, 3 s × v)`.
- Each alert fires at most once per maneuver.
- No turn alerts in OFF_ROUTE, NO_GPS or under poor accuracy.

### 5.11 Stats while riding
- Distance left: from `s` to the finish.
- Climb left: smoothed positive elevation from `s` to the end.
- Moving time.
- No ETA in v1.

## 6. Ride service & location

- **Foreground service:** `RideService` uses `foregroundServiceType="location"`. It is started from the visible activity when the rider taps *Ride*, as Android 14+ requires.
- **Permissions:** `ACCESS_FINE_LOCATION` (while in use), `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_LOCATION`, `POST_NOTIFICATIONS`. **No** `ACCESS_BACKGROUND_LOCATION`.
- **Location source:** `LocationManager.GPS_PROVIDER` at 1 s / 0 m. `GnssStatus` provides the satellite count. A cold start without network assistance can take 30–60 s or more, so "Waiting for GPS" shows the satellite count.
- **Process:** single process. Moving rendering out of the ride process is revisited only if crash logs show renderer crashes.
- **Checkpointing:**
  - Every 5 s the service saves the engine snapshot (route id, direction, mode, `s_start`, `s`, exit point, state, ride id).
  - Track points are appended to the ride's track file as they arrive and flushed at least every 10 points or 10 s.
- **Crash, swipe-away or reboot recovery:**
  - Opening the app with an `IN_PROGRESS` ride goes **straight back to the ride screen**.
  - The foreground service restarts (allowed, because the activity is visible) and recording continues in a **new track segment**.
  - Android cannot restart a while-in-use location service from the background, so guidance resumes when the rider reopens the app.
  - The exit reason is logged through `ApplicationExitInfo`.
- **Battery optimisation:** the settings screen offers a helper that opens the app's battery settings ("set to Unrestricted"). It does not request a Doze exemption directly.
- **Low storage while recording:** stop recording gracefully with a banner and keep navigating.

## 7. Offline maps

### 7.1 Source
OpenAndroMaps V5 Mapsforge `.map` files, per country or region. Example: Switzerland ≈ 780 MB zipped, dated 2026-11-04.

### 7.2 Install flow
1. *Get maps* opens the OpenAndroMaps download page in the external browser. This links to the website, not to files.
2. The user taps an install link.
   - Singletrail registers intent filters for the scheme in **both** spellings, `mf-v4-map` and `mf-V4-map`, because scheme matching is case-sensitive.
3. **Host allowlist:** only the known OpenAndroMaps mirror hosts (e.g. `ftp.gwdg.de`) are accepted. Any other host is refused, so a malicious link cannot make the app download arbitrary files.
4. A confirm dialog shows the region name, download size, and free space needed (the zip plus the unpacked file).
5. Android `DownloadManager` (system process; Android 16 job quotas don't apply) downloads one file at a time with an app-specific User-Agent.
6. Unpack into app-specific external storage `maps/`.
   - Zip-slip protection.
   - Uncompressed-size and entry-count caps.
   - A free-space re-check.
7. Validate by opening the map file and reading its header (bounding box, date). Then register it in `map_files`.

**Manual import:** pick a `.map` file through the system picker; it is copied in and validated the same way.

### 7.3 Map management
- List installed maps with size and date; delete a map.
- *Check for update* opens the region page on the website.
- Maps deleted outside the app are detected at startup.

### 7.4 Rendering
- **Library:** VTM, the OpenGL ES renderer for Mapsforge `.map` files, chosen by the **renderer spike** on the Moto G15 (§12.3, D16).
- **Multiple map files** are combined (VTM's `MultiMapFileTileSource`) for routes that cross a border.
- **Theme "Singletrail MTB"**, derived from an integrable `andromaps_*` theme:
  - High contrast for a sunlit LCD.
  - Trail colour by `mtb:scale` S0–S5; dash pattern by `trail_visibility`.
  - Clear path vs track vs road hierarchy; contour lines.
  - Bundled in the APK under `assets/theme/`, with only the pattern and symbol files it uses (92 files, 157 KB). It is generated from OpenAndroMaps' `andromaps_mtb.xml` by `tools/theme/make-theme.ps1 -AssetPrefix theme/`.
- **Elevate theme:** if the user loads it, it is selectable.
- **Route overlay:** VTM simplifies it per zoom level.
  - The route ahead is a translucent magenta band, so the trail's difficulty colour and dashes still show through.
  - The ridden part is grey, and skipped parts are a thin dark grey line.
  - Turn markers are white rings, one for each turn of a switchback group; GPX waypoints are teal dots.
  - A straight line runs from the rider to the target when off route, while acquiring, or with the heading frozen (§5.7, §5.9).
- **Attribution:** "© OpenStreetMap contributors · OpenAndroMaps" is always visible.
- **No map installed:** route on a neutral grid background. Navigation works the same.

### 7.5 Coverage check
Route detail shows "Map coverage: 100%", or "1.8 km of this route has no installed map" with a *Get maps* shortcut.

### 7.6 Later (v2+)
- Hillshading from DEM (HGT) files.
- Filling in missing GPX elevation from DEM.
- Optional swisstopo layer: Swiss Map Raster 25 converted to MBTiles on a PC, or a small online cache under swisstopo fair-use terms.

## 8. Route library & data

### 8.1 Screens
- **Library:**
  - Chip row: `[Sort ▾] [Collection ▾] [Filters ▾]`.
  - Sort by near me, stars, name, length, last ridden.
  - **Collection** (D48): *All routes (66)*, each collection A–Z with its route count, *Not in a collection (n)*, *Manage collections…*. One collection at a time.
  - **Filters** (D49) open a sheet; the chip shows how many are on ("Filters (2)"):
    - Minimum stars: any, 1+ … 5.
    - Length: any, up to 20 km, 20–40 km, over 40 km (≤ 20 000 m, ≤ 40 000 m, more).
    - Climb: any, up to 500 m, 500–1000 m, over 1000 m (same boundaries). Routes without elevation are hidden while it's on.
    - *Not ridden yet*: routes with no "last ridden" date.
    - *Loops only*.
    - *Clear* and *Done*.
  - Search over names and descriptions. Every word must match; case, accents and the German "ae/oe/ue" spellings don't matter ("hoernli" finds "Hörnli"). Not remembered across restarts.
  - Collection, filters, search and sort combine. Sort, collection and filters are remembered across restarts; a remembered collection that was deleted falls back to *All routes*. An empty result says so and offers *Show all routes* (clears collection, filters and search).
  - Selection mode (long-press): *Share*, *Add to collection* (checklist of collections plus *New collection…*), and while a collection is chosen, *Remove from "‹name›"*.
  - Import button.
  - Banner "Last export 47 days ago".
- **Manage collections** (from the Collection chip and the library menu): collections with their route counts; *New collection*, *Rename*, *Delete* (asks first and says the routes stay in the library). Names are unique, ignoring case.
- **Route detail:**
  - Map preview, stats, elevation profile (custom Canvas, no chart library), description (plain text), stars.
  - Coverage check; ride history for this route.
  - *Collections*: the route's collections, with *Edit* (the same checklist as in selection mode).
  - Actions: *Ride*, *Ride reversed*, *Share route*, *Edit name/description*, *Delete*.
- **Ride history:** all rides. **Ride detail:** track on the map, stats, *Export GPX*, *Delete*.
- **Maps** (see §7).
- **About** (library menu): version and build number, author, licence (GPL-3.0), link to the source and releases, credits (OpenStreetMap, OpenAndroMaps theme, VTM).
- **Settings:**
  - Off-route threshold, beep volume, dim level, compass on/off, map orientation.
  - Low-power threshold, watched folder, debug trace opt-in, battery helper.
  - *Delete all ride history*, *Full backup*, *Restore*.
- **"Near me":** one location request when the library opens (permission while in use), never continuous. The distance is a straight line to the nearest point anywhere along the route, where a ride would join it (D14), measured on an outline stored with each route (D46).

- **Settings:** DataStore. The library's sort, collection and filters are stored there (§8.1).
- **Schema:** exported (`exportSchema = true`), with tested migrations from v1 on (§12). v2 added `routes.outline` (Room auto-migration); routes stored under v1 get their outline from their GPX copy in the background when the app starts. v3 adds `collections` and `route_collections` (new tables only, Room auto-migration).

### 8.3 Files
- `filesDir/routes/<id>.gpx`: normalised copy of the imported GPX, kept for sharing and re-processing. A route updated from a newer file gets a new file (`<id>-<suffix>.gpx`), so the old copy stays intact until the database points at the new one; `gpxPath` always names the current file.
- `filesDir/rides/<id>.track`: append-only CSV.
  - One line per fix: `timeMs,elapsedMs,lat,lon,ele,acc,speed,bearing,segment` (`timeMs` is the fix's GPS UTC time, for the GPX export).
  - Survives crashes; a partial last line is ignored.
  - Converted to GPX on export.
- `filesDir/traces/<rideId>.jsonl`: opt-in debug trace (§11).
- `getExternalFilesDir()/maps/*.map`: map files.
- `filesDir/themes/`, `filesDir/logs/`.
- `cacheDir/import/`: temporary files during import.

### 8.4 Import pipeline
1. **Receive.** Sources:
   - Share/"open with": `ACTION_VIEW` / `ACTION_SEND` for `application/gpx+xml`, `application/octet-stream` + `.gpx`, `text/xml`.
   - Picker: `ACTION_OPEN_DOCUMENT`, multi-select.
   - Watched folder: persisted `ACTION_OPEN_DOCUMENT_TREE`, read-only, scanned when the app opens.
   - URL: `https` only, ≤ 20 MB. GPX, or a zip of GPX files (a **route package**, for example from a GitHub release): the zip is saved and imported like a picked one.
   - Zips (backups and route zips) from the picker, "open with" or the share sheet are detected by their signature (§8.5).
2. **Parse safely** (§9): GPX 1.0 and 1.1.
   - `trk/trkseg/trkpt` → track; multiple segments are joined in order.
   - `rte/rtept` → treated as a track.
   - `wpt` → waypoints.
   - `name`/`desc` → name/description, HTML stripped. Exporters' boilerplate is dropped from names: komoot's "GPX Download: " prefix (D47).
3. **Multiple tracks:** ask "Import as N routes / Join into one".
4. **Identify:**
   - `geometryHash`: SHA-256 of coordinates rounded to 5 decimals, after dropping duplicate points. Also computed for the reversed geometry. Coordinates are rounded to the 7 decimals our GPX writer stores first, so a route keeps its hash through our own export and re-import.
   - **Exact match** → "Already in library" (or "Same route, reversed").
   - **Similar** (simplified geometries within 10 m and lengths within 2%) → "Update existing route (keeps stars and rides, recomputes maneuvers) / Keep both".
   - **Tombstoned** (watched folder only) → skip silently. *Show ignored files* lists these.
5. **Prepare:** stats, elevation profile, maneuvers (both directions).
6. **Store:** route row + GPX file, in one transaction. Temporary files are cleaned on failure.
7. **Collections** (D48). A route "counts" for its collection when it was added, updated, or found already in the library (exact match); skipped and failed routes don't.
   - **A zip** (picked, shared, opened, or a route package from a link): its routes go into a collection named after the zip, without `.zip` ("SchweizMobil-MTB-Ostschweiz"). A routes zip whose manifest names a collection (§8.5) uses that name instead. An existing collection of that name (ignoring case) is reused, so importing the same zip again groups routes that are already in the library. No question.
   - **Several GPX files at once** (picker multi-select, `ACTION_SEND_MULTIPLE`): after the last one, if two or more routes count, the app asks *"Put these N routes in a collection?"*: a new name, an existing collection, or *No*. Zips in the same batch keep their own collections and aren't counted.
   - **Watched folder:** a file in a subfolder joins a collection named after its own folder ("komoot St. Gallen/x.gpx" → "komoot St. Gallen"); files at the top level join none. No questions, as for the rest of the scan. Files imported before collections existed join when they change; group them by hand otherwise.
   - **A single file:** no collection.
   - A collection renamed later isn't matched by its old name: importing the zip again then makes a new collection.

**Concurrency:** imports run one at a time (a single-threaded import queue), so two sources delivering the same file cannot both insert it.

### 8.5 Sharing vs backup (privacy)
- **Share routes:** the selected routes as GPX (one file, or a zip for several), containing name, description, track and waypoints only. **No rides, no stars.** Sent through the Android share sheet using `FileProvider` URIs.
  - Several routes shared while a collection is chosen: the zip is named after the collection and its manifest carries `collection` (the name), so importing it recreates the collection (§8.4 step 7). No other collections are shared.
- **Full backup:** a zip containing:
  - `manifest.json` (format version, app version, created date, `kind: "full-backup"`).
  - `routes/*.gpx`.
  - `routes.json` (metadata, stars, and each route's collection names).
  - `collections.json` (name, created date; empty collections too).
  - `rides/*.gpx` + `rides.json`.
  - Settings.

  New fields are optional: older backups restore without collections, and older app versions ignore them.

  Before saving, the screen states: **"Contains your ride history (location tracks)."**
- **Restore / import a zip:**
  - Detects `full-backup` vs `routes`.
  - For a backup that isn't yours, it offers **routes only** as the default. "Yours" means the manifest's owner id matches this installation's (a fresh install, or cleared app data, gets a new id, so a restore onto a new phone asks).
  - **Merge rules:**
    - Routes are matched by geometry hash; the local name, description and stars win.
    - Imported rides attach to the matched route.
    - Rides are de-duplicated by ride UUID.
    - Collections are matched by name, ignoring case; missing ones are created. Memberships are added, never removed.
- **Cloud backup off:** `dataExtractionRules` exclude cloud backup and allow device-to-device transfer. `allowBackup` is set accordingly for API < 31.

### 8.6 Deletion
- Delete one ride, or *Delete all ride history* (with confirmation).
- Deleting a route asks "Also delete its N rides?". Kept rides keep `routeNameSnapshot`.
- Deleting a route that came from the watched folder writes a tombstone.
- Deleting a collection (asks first) removes the collection and its memberships; its routes stay in the library.

### 9.1 Requirements

## 12. Testing strategy

### 12.1 Unit tests (JVM, fast)
- **`:core:gpx`:**
  - Fixtures: komoot, Garmin, Strava, OsmAnd and Trailforks exports; GPX 1.0; `rte`-only; multi-track; missing `ele`/`time`; namespaced extensions.
  - Malicious files: XXE attempt, entity expansion, oversized, HTML in `desc`.
- **`:core:nav`:**
  - Haversine and cumulative distance; elevation smoothing and hysteresis.
  - Turn detection on synthetic shapes: a gentle curve (no turn), a 90° corner, a switchback stack (grouped), an S-bend.
  - Matching on synthetic traces with noise (σ 5–15 m), including an **out-and-back** (must not trigger reverse) and a **figure-8** (must not jump).
  - Off-route enter/exit hysteresis, and the **switchback overshoot** case (target must be the exit point, never the leg below).
  - Reverse detection and undo suppression; loop start-from-nearest and finish; NO_GPS on fix gap.
  - Alert timing at 5 / 20 / 45 km/h, including fix-age extrapolation.
- **Data:** geometry hash stability, similarity check, merge rules, tombstones.

### 12.2 Replay harness
- Debug traces (JSONL) and the GPX + timestamps of real rides run through the engine in tests, with assertions on alert positions.
- An in-app **Simulate ride** debug mode feeds a trace into `RideService` as fixes, to exercise the real UI, beeps and dimming at a desk.

### 12.3 Renderer spike (decision gate before map UI work)
- **Setup:** Mapsforge and VTM, each with OpenAndroMaps Switzerland, a 30 km route overlay, heading-up rotation at 1 Hz, and the Singletrail MTB theme draft.
- **Measured on the G15:** frame smoothness while panning and rotating, time to first render, memory, and **battery %/h with the screen on** (30 min each).
- **Output:** a short decision record that updates D16.

**Decision record (2026-11-11): VTM.**

Both test apps used the same setup:
- the Switzerland map and the 35 km route;
- zoom 16, with the rider 3/4 down the screen;
- the theme draft, with the screen at 50% brightness;
- *smooth* mode, where the map moves and turns every frame (the hardest case);
- 30 minutes each on battery.

| On the G15 | VTM | Mapsforge |
|---|---|---|
| New map pictures per second | 60 (every frame) | 9.6 (8.6–10.7) |
| Screen frames p50 / p95 / p99 | 16.5 / 21.5 / 25.0 ms | 16.5 / 26.0 / 30.5 ms |
| Slow frames | 0.04% | 0.28% |
| First full screen after start | 0.74 s (16 tiles) | 1.87 s (90 tiles) |
| Memory (PSS) | 79–105 MB | 308–369 MB |
| Battery | 8.0%/h (484 mAh/h) | 14.0%/h (847 mAh/h) |
| Average current | 511 mA | 810 mA |
| Phone temperature | 28 → 31 °C | 30 → 34 °C |
| Spike APK (two ABIs) | 1.9 MB | 1.4 MB |

- **Why Mapsforge loses:**
  - Its screen runs at 60 fps by shifting and turning the last picture it rendered.
  - It renders a new picture in software only about 10 times a second; its layer thread would allow 33.
  - That picture is a bitmap 1.5× the screen diagonal on each side, which heading-up needs with the rider low: about 3,950 px square and 62 MB, and it keeps two of them.
  - The extra 300 mA and the extra ~250 MB most likely come from this.
  - Its labels turn with the map.
- **What VTM does:**
  - It draws vector tiles on the GPU in every frame.
  - Labels stay upright.
  - It needs no cache tuning.
  - Even with the map moving every frame and no dimming, it stays inside the 12%/h budget.
- **Fairness of the comparison:**
  - The phone wasn't recharged between the runs, so the Mapsforge run started at 79% and 30 °C, against 84% and 28 °C for VTM. That can't explain 60% more current.
  - Both runs had the same once-a-minute memory probe, which causes a ~0.1 s hitch.
- **Not measured:** *step* mode, with one redraw per fix (D33). It would narrow the battery gap but not the memory gap, and Mapsforge has no smooth option on this phone.
- **For the app:**
  - Libraries: `vtm`, `vtm-android` and `vtm-themes`, plus the native libraries for arm64-v8a (and x86_64 for the emulator).
  - Several map files are combined with `MultiMapFileTileSource`.
  - The theme stays a Mapsforge render theme, which VTM loads as is.
  - Version: 0.30.0 from JitPack for now, because 0.31.0 doesn't build there. A source build comes before F-Droid (v2).
